# Yöneticinin aşama incelemesi

## Aşama A için teslim kapısı — açık kontroller
- GM sunucusunun ilk yazılan sürümünde yetkisiz yanıtta `?token=<gerçek token>` gösteriliyor. Bu token doğrulamasını etkisiz kılar; hata yanıtı/sunucu HTML'i yetkisiz kullanıcıya token veremez. Token sadece kullanıcının açık debug ekranı/yerel debug logu yoluyla edinilir. Testte yetkisiz yanıtın tokenı içermediğini doğrula.
- Origin kontrolünde contains('localhost') veya contains('127.0.0.1') geçerli kontrol değildir. URI parse + tam host/scheme/port allowlist uygula; `http://localhost.evil.example`, `http://127.0.0.1.evil.example`, `null` origin ve beklenmeyen port reddedilsin. Wildcard Access-Control-Allow-Origin verme. Panel aynı origin üzerinden çalıştığından CORS açmak gerekmeyebilir. Token request body/header yoluyla tercih edilir; URL/log/historyde tokenı yayma.
- Sunucu kendi başlangıcında da release engeli uygulasın; sadece UI'da düğmenin gizlenmesine güvenme. Test/debug için kontrollü enjeksiyon olabilir ama release runtime devre dışı olmalı.
- Tekrarlı komut aynı id ile aynı sonucu döndürmeli; id+farklı payload çakışması ret. Geçersiz/negatif/aşırı sayıların kalıcı state'i değiştirmediği kontrol edilsin.
- Panelin hazır olması yalnız HTML/endpoint yazılması değildir: adb forward üzerinden PCde gerçek state okuma, bir demo mutasyon, tekrar gönderme ve kalıcılık sonucu doğrulanacak. Kullanıcının profilini/sensör geçmişini test uğruna sıfırlama.
- Kullanıcı Düzenlemeler.txt dosyasını aktif düzenliyor olabilir. Yöneticiye haber vermeden bu dosyayı değiştirme/geri alma; aşama kodu dışında görülen yeni notları kapsama sessizce alma. Son konuşma talimatları REVIZYON_02.mdde kayıtlı.
- Fiziksel yürüyüş testi şu an yapılamıyor: telefon kısa USB kablosuyla PCye bağlı; kullanıcı bunu bildirdi. Aynı denemeyi tekrar isteme. İvme/GPS callbacklerinin geldiği ve deterministik adım işleme testleri ayrı kanıt; gerçek yürüyüş sonucu bekleyen olarak raporlanmalı. İleride kullanıcı uygunsa kabloyu çıkarıp uygulama açıkken yürür, sonra yeniden bağlanır.
- Canlı GM durum çıktıları koordinat, UUID ve oturum tokenı içerebilir. Bu raw runtime dosyalarını Git'e ekleme. Commitlenecek kanıtlar yalnız sanitizasyonlu sonuç özeti/test/build kayıtları olsun; tokenı/konumu dokümana basma.
